# Part 6: Version Control with GitHub (1-2 min)

**[SCREEN: Show GitHub repository]**

> "We used GitHub for version control throughout development. Our branching strategy has two main branches: `main` for production-ready code and `staging` for testing before release."

**[SCREEN: Show branch list or PR]**

> "For each new feature, we created individual feature branches - like `feature/notifications`, `feature/gamification`, or `fix/message-polling`. This isolated development work and prevented conflicts.
>
> When a feature was complete, we opened a pull request to merge into staging. PRs required code review to catch bugs, ensure code quality, and maintain consistent patterns across the codebase."

**[SCREEN: Show a merged PR or commit history]**

> "After testing on staging, we merged to main for production deployment. This workflow gave us a clear audit trail of changes - every feature, bug fix, and refactor is documented with descriptive commit messages.
>
> GitHub also served as our backup and collaboration hub - multiple team members could work on different features simultaneously without stepping on each other's code."
